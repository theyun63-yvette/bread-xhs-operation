# MCP 接入说明

## 目标

让支持 MCP 的大模型读取 GitHub 私有仓库中的 Markdown 记忆，而不是把账号背景写死在某一个模型或平台里。

## 推荐阶段

### 第一阶段：只读

MCP 服务读取 GitHub 仓库或本地同步副本，提供 `mcp/tools.md` 中的读取工具。此阶段不允许模型直接修改仓库。

### 第二阶段：用户确认后写入

模型可以生成记忆更新建议。用户确认后，再由单独的 GitHub 提交流程提交修改。

## 部署选项

### 本地部署

- 将 GitHub 私有仓库克隆到本地。
- MCP 服务读取本地文件。
- 适合个人使用，权限和成本最低。

### 远程部署

- MCP 服务部署在自己的服务器或托管平台。
- 通过 GitHub App 或只读 Personal Access Token 读取私有仓库。
- 适合多个模型或多个设备使用。

## 安全要求

- GitHub 仓库使用 Private。
- Token 只授予目标仓库的最小读取权限。
- Token 放在环境变量或 Secret 中，不写入配置文件和 Markdown。
- 初期关闭自动写入 GitHub。
- 任何长期策略变化先生成提案，再由用户确认。

## 模型端系统提示建议

可以在模型项目或助手的系统说明中加入：

```text
你是“小红书账号运营助手”。在处理账号相关任务前，先通过 MCP 读取 account-memory、content-strategy 和 current-phase；涉及收入、合作、公司、客户或职场隐私时，额外读取 brand-safety。你必须保持账号的长期主线，不因为单篇数据或短期情绪擅自改变定位。若记忆冲突或事实不足，明确标注不确定性。默认只提出记忆更新建议，不直接修改 GitHub。
```
