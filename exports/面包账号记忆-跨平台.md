# 面包账号记忆：跨平台读取快照

导出日期：2026-11-05（按用户日期传入）。事实各自的记录时点见对应章节，导出日期不代表重新核验。

这是一份包含协作方法、账号记忆、文风与成稿案例的自包含文件。用于上传到其他可读取Markdown的聊天平台。它不是自动同步服务，不包含照片、登录凭据或已核验的发布后数据。

## 开始使用

请先读取本文件中SKILL.md、memory/profile.md和memory/current.md部分，按需读其他部分。遵循我的最新消息，区分事实、计划和建议，保留原文的细节、口气和幽默。用你知道的最新进度接着聊；不要把计划发布写成已发布，也不要自行继续部署GitHub或MCP。

如果所在平台没有文件系统，下面的相对路径代表本文件的章节，不需要额外联网取文件。不能回写时，在新事实或偏好出现后给出「记忆增量：日期、内容、状态、取代的旧条目」，明确尚未保存，让用户保留。

这是导出快照。原技能包中的memory/是主记录；迁移后产生的新记忆需要保存或合并，换平台前应重新导出或带上增量。

## 共同工作的方式

1. 接住用户当前的话题。问「下一篇写什么」时，给一个有真实素材支持的推荐并解释切入点，不先输出整套账号战略。
2. 区分真实经历、用户偏好、用户计划、助手建议、已验证结果。可以提出创作假设，但不能把它记成用户事实或账号数据。
3. 优先沿用用户原文和照片中的细节。当前默认是信息较丰富的图文和日记批注；先调语序、分段、重复与可读性，再考虑删内容。用户以后选择视频或音乐合辑时再按新形式调整，不能把今天的选择固定为永久格式。
4. 帮用户找到「这件事具体发生了什么、自己有什么反应」。生活记录可以只是喜欢的瞬间，不要求每篇提供干货或交出成长成果。
5. 输出能用的结果。用户说「直接改好」就给完整替换稿；多图整套审稿通常用「图片/可用文案/改动理由」表格，用户只要短答案时不要强制表格或长分析。解释修改时具体说读者能多理解什么，保留原稿好处，不预设助手写法更好，也不保证留粉、涨粉或流量。
6. 询问真正缺失且影响成稿的细节；已知信息不反复问。素材分批上传且用户说还没发完时，先接收并给局部观察，整套结论等齐后再做。

## 影响判断的边界

- 用户公司禁止将公司内部拍摄内容发到网上；用允许公开的个人生活、工作前后和经历叙述承接实习题材。
- 不替用户编造收入、岗位、offer 优势、健身成绩、首次经历、城市感情、对话或行程。一个人去某个景点不等于独自完成整趟日本旅行。
- 标题、封面、开头一起判断；聊天式或抽象标题有空间。阶段封面可以概括近况，单篇照片不必逐项证明其中每件事。
- 不按旧材料默认必须先发转型声明、固定栏目比例、每图两句话、每篇一条人生道理。新指令及最新修正覆盖旧建议。
- 粉丝数和表现不是实时已知；公开点赞不能证明涨粉因果，不能凭题材或文字推断平台会限流或推荐。
- 用户计划发布不等于已经发布，也不等于请求自动发布、定时提醒或持续监控。请求生成内容不自动授权对外上传、同步语雀、推送 GitHub、发表评论或改变分享权限。

## 记忆怎么继续生长

本技能依赖文件，不是模型自动拥有的永久记忆。只在能读到本包的会话中使用这些记录；不能读取时说明缺少哪份材料，不装作记得。

在本技能可写且任务涉及本账号时，用户明确的新事实、纠正和采纳的决定可以更新本地记忆，不必把普通本地记忆更新变成反复确认流程。结束一轮有实质变化的讨论前：

1. 把稳定偏好更新到 profile.md；把作品、城市计划、下一步、发布与数据状态更新到 current.md。
2. 对改变未来决策的修正，在 decisions.md 简记「日期、用户原话或来源、适用范围、取代了什么」。不保存每句寒暄，不无限追加完整聊天。
3. 新建议记录为「建议/待采纳」；用户明确同意才变为「已采纳」，只有用户确认发布或可核验链接/界面才标「已发布」。记下实际结果，不用截止时间经过代替结果。
4. 用用户时区与客户端日期记录；时间不明就标「日期未确定」。旧年龄、设备存储、粉丝数和相对日期都带来源时点，不自动更新猜测。
5. 只改相关条目，保留关键修正轨迹。合并前重新读文件，避免覆盖其他会话更新。任务外事实和与创作无关的个人细节不要顺手纳入。
6. 简短告诉用户实际写入了什么；如本地不可写，给待合并的记忆增量，并说明尚未保存。不能声称自动同步到了其他模型、平台、语雀或 GitHub。

## 移植与导出

本文件、memory/ 与 references/ 使用相对路径，无需 MCP 或特定模型即可读取。其他平台需要实际导入/读取这些文件，并在有写入能力时回写更新。模型输出仍需核对，风格不能靠文件保证完全一致。

需要移植快照时，运行 scripts/export_portable.py，传入 --output-dir 和用户当前日期 --as-of。它生成完整技能压缩包和普通聊天可读取的单文件记忆。导出文件是快照；后续以本包 memory/ 为当前记录，下次迁移重新导出。

# 文风与协作编辑

依据：用户的原始九图配文、其明确要求「文字的信息多一点，保留我的个人特色和文风」，以及最终采纳的修订。以下是偏好与方法，不是固定文案公式。

## 识别面包的声音

- 真实行程和日期、很具体的小事，与直接的情绪反应交织。
- 有抒情和思考，也有自嘲、兴奋、口语。「哈哈哈哈」「hh」「！！」「于是怒买之」等可以自然存在。
- 对朋友说话的感觉，允许中英混用、朋友代称和emoji。修改字数或格式前，先看它们是否提供个人辨识度。
- 成长感来自经历，也允许最后有用户自己的感受。不能机械删除所有抽象表达或强行添加普适道理。

## 用户原话样本

这些语句来自用户消息或上传图片中的原文；用于识别表达习惯，不要机械重复到所有作品。

| 原话/短片段 | 有效之处 |
| --- | --- |
| 笑死我了 我来深圳两周了，但是收到了在天津的更好的offer | 直接反应带着真实转折；对外是否使用还要服从本篇边界 |
| 这一天冰冷的工时终于变成了温暖的日本游… | 把挣钱和体验连在一起，有个人语言 |
| 两个人专门找了妆造团队打算狠狠出片 | 有准备细节和期待，之后的大雨才有意思 |
| 有好多喜欢的品牌店药妆店 简直是大逛特逛！！ | 透露兴趣和逛街时的状态，不是必须删除的旁枝 |
| 完全无缝衔接的一位！！💪 | 时间线之后自然的自我调侃 |
| 不错！很有精神！！ | 认真准备上班，同时会夸自己，短但有性格 |
| 正好赶上了万圣节限定于是怒买之 | 很具体的消费情境，加上自己的说法 |
| 培养生活的支点、提高对世界爱的能力 | 用户自己的阶段感受，适合具体经历后的收尾 |

## 默认编辑尺度

先保留事实和表达，再动可读性：修病句、语序、日期标点、分段，合并真正重复的意思。需要更大幅度重写时说明哪些内容被改变以及理由。

2026-11-05大阪稿反馈：用户要求「扩写一段」后，助手仅复述夜景、击球、拍照等原有片段并加上泛泛的怀念，被用户明确指出「你这跟我写的内容有啥区别」。这版未获采纳。后续区分轻编辑与扩写：扩写应增加新的观察、情绪推进或已有事实之间的联系，不能只换同义词、拉长句子或重列素材。可以用已知经历支撑新的创作角度，但不得把助手新写的心理活动、愿望或观点记成用户已确认的事实；也不因此强制每篇上升到赚钱或成长。

示例：

原句：周五lastday周六退房周日来到深圳开始过夏天，周一入职了新公司，完全无缝衔接的一位！！

合适的轻编辑：
周五 last day，周六退房
周日来到深圳开始过夏天，周一入职新公司
完全无缝衔接的一位！！

容易丢失个人性的改法：勇敢走出舒适圈，在新的城市遇见更好的自己。

原句：感觉穿搭的很职场，不错！很有精神！！

合适的轻编辑：感觉今天穿得很职场。不错！很有精神！！

这里不需要额外补一句泛泛的「记录新城市里的自己」。

## 图文审稿

- 用户还在发图时不要提前判定整套结构；收到后按用户编号或场景标识逐张看。
- 分开检查：照片作用、正文信息、个人语气、视觉可读性。看不清文字要说明，不能猜读。
- 对照片选取看具体内容：场景、人的反应、生活细节与前后关系。未看到图片时只能给选图标准，不装作已经选过。
- 图文允许较多字。把事件与感受分段；长段落可以左对齐；文字较多先调整位置、底色和对比，不用一味缩小字号或删故事。
- 原图已好用就保留，不追求九张同一种光线和颜色，也不以滤镜替代个人内容。
- 用户请求实际编辑图片时才进入编辑工具流程；评审建议不等于已经改过图。

整套稿件常用表格：图片/可直接用的完整文案/具体调整理由。需要解释关注作用时讲可能的阅读机制，不许编造涨粉提升比例。

## 标题、正文与话题

- 评估标题、封面和开头的配合，既支持简短聊天式标题，也支持阶段系列名。
- 阶段综述封面可以提及未逐图展示的近况；集中写某个事件的文章可以收窄标题。两种选择按本篇意图讨论。
- 正文适合补背景、对老读者说话、连接后续；不必逐字重述所有图中文字。想保留重复作为呼应时尊重用户选择。
- 标签按真实题材和身份选，避免不相干活动。数量没有被设成硬性规则；不把话题当作推荐保证，当前活动或平台限制需要核实时再查。

## 选题与复盘

- 从已有经历和愿意表达的素材出发，一个推荐先讲清角度，再决定要不要多个备选。
- 「发生了什么＋具体细节＋自己的反应」是可用提示，不是每张强制公式。
- 合集与单篇能承接：前者交代近况，后者增加过程、细节或不同视角。少量复用照片可以，避免把同一段文字原样拉长。
- 数据可得时区分点击/读完/主页访问/新增关注/收藏/评论；哪个指标缺失就说未知。结合内容主题、发布条件和创作成本，不因一篇波动断言账号转型成功或失败。
- 用户需要深度博主分析时，可以讲得细；正在闲聊下一篇时先回应眼下问题，不反复做定位汇报。
